# Development and creator workflows

Node.js 22+. Run npm ci, npm run dev, npm test and npm run build. Dev and build generate an embedded IIFE player bundle. The development server binds to loopback; the built static editor does not expose credentialed integrations.

## Playable games
Load Treasure Run, Sky Steps, Meadow Explorer, Physics Playground, Sky Transit (ride a moving shuttle to collect a key and open its gate) or the two-level Adventure Campaign. Press Play; use Pause and Resume to freeze and resume simulation, including physics, animated objects, patrols and timed events. Pause clears keyboard/touch input and stops active sound effects; resume does not replay them. Restart and Stop discard pause state. Exported games have the same controls. Move using WASD, arrows, on-screen controls, or a standard gamepad's left stick or D-pad. Jump with Space, Jump, or the gamepad's primary button. Starting or restarting play focuses the game viewport; Tab moves focus to other controls, and gameplay keys no longer intercept keyboard activation of buttons. Keyboard and touch input are cleared when the document becomes hidden. Gamepad stick input uses a dead zone; browser support and device behavior still need real hardware verification. Collect items and reach the goal. Stop restores the authored scene. Assign roles (decoration, player, solid, collectible, goal) to supported primitives and characters. One player per scene. Hazard objects respawn the player; checkpoints change the current respawn location and dispatch a checkpoint event. Score and collectibles reset on respawn. Keep checkpoints and their respawn locations clear of hazards and solid geometry. Undo/redo, project JSON export and self-contained HTML game export are supported. No native executable builds or shared-state multiplayer yet. Local development rooms can exchange player presence while playtesting the exact same authored level.

## Level Manager and game presentation
Create, duplicate, rename, reorder and delete up to 32 levels; a duplicate is inserted immediately after its source and activated. It receives independent scene settings, objects and rule IDs, with event-object references remapped to the copies. Assets and prefabs remain shared; editing switches the active scene while assets and prefabs remain shared. Each level has its own entities, physics, logic, audio and environment. The active scene is autosaved along with all inactive levels. Undo restores previous edits including level deletion. Play tests the current level; Play campaign starts at the first level, and Next level appears after completion. HTML export includes the full ordered campaign, uses the project name as an escaped HTML title, and declares a content security policy allowing the bundled runtime and embedded assets but denying remote connections and scripts. The policy is scoped to the exported game, not a production editor deployment. Every campaign level needs a player and a goal with auto-win enabled or a win rule. This validates structure, not solvability. Score and in-level progress reset between levels. Exported multi-level games offer Save progress and Load progress, using a small versioned local JSON file that resumes the highest unlocked level from its start. The project fingerprint detects accidental mismatches between game versions; it is not cryptographic authentication or anti-cheat. It does not save in-level position, score, inventory, or completion of the final level. No branching scene graph yet.
Game UI and camera controls customize HUD title, text color, score, collectibles, messages, a level timer and follow/overhead camera distance. The optional timer displays simulated elapsed minutes and seconds, stops when the level is won and resets on level restart; it does not announce every tick through the live status region. Both editor and standalone player use the same simulation clock. Workspace and inspector filters and scene search organize editing controls. Rendering quality is global: resolution scaling, optional directional shadows and 512/1024/2048 shadow maps. Diagnostics report approximate FPS, scene mesh/vertex counts and render-buffer dimensions. These are local observations, not a production performance benchmark. Babylon WebGL context-loss/restoration notifications suspend simulation and clear input/audio, defer editor synchronization while graphics are unavailable, and resume after Babylon restores resources without consuming the lost interval. The editor keeps authored data available for export. Real GPU/driver failures may not restore; no guarantee of recovery on every device.

## Project management and assets
The active workspace autosaves to IndexedDB. Legacy localStorage data migrates without deleting its old backup. The named project library stores independent snapshots; Save project copy, Open, Update or Delete explicitly. These are snapshots, not multiple automatically saved live workspaces. Browser storage can be evicted; export backups. Current editor tabs compare a workspace revision atomically before each autosave. If another tab has saved first, autosave is disabled and the unsaved scene remains available for export; reopen the latest saved project or explicitly confirm replacement. Close older-version editor tabs before using this feature, since their saves do not participate in the revision protocol. This is conflict detection, not collaborative merging.
Import a self-contained uncompressed GLB (2 MiB per file, 3 MiB aggregate); external URIs and glTF extensions are rejected. Models retain their materials and are decorative. The importer also checks embedded buffer/view and accessor ranges (including strides and sparse declarations), with at most 250,000 elements per accessor and a conservative 16 MiB aggregate decoded-accessor budget. Scene graph checks also reject cycles, multiple parents, duplicate scene roots, invalid node/mesh references and hierarchies deeper than 64 nodes, with limits of 2,048 nodes, 64 scenes, 512 meshes and 4,096 declared or instantiated primitives. Embedded textures are limited to static PNG and baseline/extended/progressive 8-bit JPEG headers with dimensions at most 4,096 per axis, 16 Mi pixels aggregate per GLB, 64 images and 128 textures. Invalid texture sources and animated PNG chunks are rejected before rendering. Header checks are not full image decoding, CRC verification, or a complete glTF validator, and do not bound every renderer allocation; it is not a full security validator. Prefabs can be placed as independent snapshots or linked copies. Explicit Update from selected propagates geometry, character customization, material and asset changes to linked objects across all levels, preserving each object's name, transform, role and animation. Detach turns a linked instance into an independent object. Removing a prefab detaches its instances; no nested inheritance or automatic live propagation. Extension packs export and import validated prefabs, referenced models and declarative gameplay rules, with fresh IDs. They are data-only, not executable plugins. Creator tools additionally load version-1 JSON manifests with explicit add/environment/presentation/physics/audio capabilities and bounded typed parameters. The built-in Platform builder demonstrates literal parameter substitution. Imported tools remain in the current session (up to 16), can be exported, and produce the same reviewed atomic edits as AI commands. No JavaScript execution, arbitrary expressions, file/network access, delete/edit commands or background plugin execution. This is an initial declarative extension contract, not the full executable plugin SDK.

## Physics and editing
Box entities with the platform role provide one-way player supports. Their optional patrol uses the same simulation clock as rendering; riders follow horizontal motion and rising or descending tops, detach on jump, and respect solid obstructions. Up to 128 supports per level; they do not push dynamic bodies or act as solid side walls. Static swept axis-aligned collisions, gravity, jumping, raised platforms, respawn, height-aware triggers and fixed-substep integration. Static colliders are indexed in a bounded uniform grid once per play session; swept queries preserve authored ordering and fall back to scanning for oversized queries or colliders. Dynamic bodies and counter gates are merged separately. Equivalence tests compare indexed sweeps against brute force; no real-world throughput or FPS certification yet. Optional per-level ledge jump grace (coyote time) and jump input buffering each accept 0–0.3 simulated seconds. They are consumed on a successful jump and cleared on respawn; holding the jump control does not generate repeated jumps. Legacy levels default to disabled, while Sky Steps enables 0.12 seconds of each aid. Direct move/rotate/scale handles with optional snapping and undo. Character collisions remain conservative bounds. Dynamic primitive objects now use bounded translational AABB physics. Assign the dynamic role and configure mass (player push response), restitution, ground friction and initial velocity. Up to 64 per level; they fall, bounce, block the character and may be pushed. Simulation is separate from authored state. This is a lightweight ordered collision solver, not a full rigid-body engine: no angular motion, joints, true sphere/mesh contacts, conservation of momentum, robust stacks (moving one-way supports are separate). Bodies should start above surfaces and outside obstacles. Terrain contact is conservative; upward steps can block objects.

## Terrain and environment
Create a terrain object and edit its seed, grid resolution, amplitude and frequency. It uses deterministic triangle heights for rendering and center-point ground contact; terrain is axis aligned with positive scale and cannot be assigned another gameplay role or animated. Large cliffs, overlapping heightfields and extreme scales have limitations; this is not general mesh collision. Meadow Explorer is a terrain example.
Environment Studio sets sky/background color, ambient and directional light, sun direction, intensity and color, and exponential fog. Day, sunset and night presets are static settings, not an animated weather system. Optional directional shadow maps are available; no HDR environment map or volumetric lighting yet.

## Modeling, characters and animation
Model Studio supports editable cube topology, numeric vertex editing, vertex duplicate/delete, triangle add/delete, subdivision, validation and flat or area-weighted smooth shading. Smooth normals are averaged by authored vertex index and shared across projected UV seams; flat remains the legacy default. This does not provide crease controls or custom split normals. Limits: 2,048 vertices and 4,096 triangles per mesh. Custom editable meshes may be decorative or solid. Solid meshes use a conservative world-axis-aligned collider computed from referenced vertices, including translation, rotation and signed scale; thin axes have a minimum thickness. This supports static obstacles, platforms and counter gates but not concave or triangle-accurate mesh physics. Imported GLB models remain decorative. Select Pick vertex in viewport, then click a visible triangle to select its nearest vertex; an editor marker highlights the chosen point. Numeric local-space coordinate editing remains the way to move vertices. Triangle extrusion, individual and whole-mesh face winding reversal, whole-mesh reflection, tolerance-based vertex welding, and OBJ import/export are supported. Clean mesh removes unreferenced vertices, duplicate faces (including opposite winding), and triangles with near-zero local area; it preserves surviving face order and winding and refuses to remove the entire surface. Cleanup is undoable and does not repair holes or non-manifold edges. Subdivide entire mesh splits every triangle into four with one shared midpoint per edge, retaining shape and winding. The operation is undoable and rejects changes exceeding topology limits; it is not a smoothing subdivision surface. A separate Smooth subdivision operation uses Loop weights to round original vertices and generate shared edge vertices, including boundary handling for open surfaces. It rejects duplicate or degenerate faces, unused vertices, inconsistent winding and nonmanifold edge or vertex connectivity, and honors the existing topology quotas. This is a destructive, undoable single subdivision step, not a live modifier or crease-aware surface system. Custom meshes can also export a self-contained GLB containing local geometry, flat or smooth normals, projected UVs and solid PBR color/metallic/roughness/emission factors. Procedural textures, transforms, gameplay and animation are not included in this model export. OBJ import is geometry-only, with bounded vertices and triangles, negative indices and fan triangulation of convex polygons; normals, UVs, material files and external references are ignored. Local inflate, deflate and smooth brushes operate around a selected vertex with adjustable radius and strength; each stroke is an undoable edit. This is a low-resolution vertex operation, not continuous brush painting or adaptive remeshing. Custom meshes support automatic dominant-axis UV projection or explicit XY/XZ/YZ projection. No UV island editor, direct vertex dragging or Boolean tools.
Characters are procedural articulated low-poly figures with adjustable proportions, skin, clothing, hair, shoes, and nine joint angles. Automatic walking and jumping poses drive the player when enabled. Decorative characters also have a joint animation timeline: capture all nine joint angles at zero and subsequent times, linearly interpolate, loop during play or scrub a nonlooping editor preview alongside transform animation. Clips are bounded to 128 keys and 60 seconds. They are saved in rig settings and therefore shared by explicitly updated linked character prefabs; player characters continue to use the authored base pose or automatic locomotion rather than decorative clips. This is a rigid mesh hierarchy, not skinned skeleton animation, inverse kinematics or motion retargeting.
Transform keyframes support decorative objects, linear, smooth ease-in/out or stepped interpolation, forward and ping-pong looping, and scrubbing. Older clips default to linear forward looping; the editor preview remains a single forward pass. Ground, terrain and gameplay roles are excluded to preserve static collision. PBR primitive materials support color, roughness, metallic and emission. Optional procedural checker, brick, stripes, grid and noise textures are generated locally as bounded RGBA images with tint and independent UV repeats. They are stored as parameters, not external resources. Static PNG/JPEG image textures can be imported locally (2 MiB source and 4096px dimension limit), normalized to an opaque 128×128 RGBA texture and saved inline with the material. One texture source per material; choosing procedural or image replaces the other. At most 48 image-texture references across all levels and prefabs; no remote resources or AI-supplied pixel data. Image textures appear in editor and standalone game exports; separate model GLB export still uses solid material only. This is deliberately low-resolution, not a professional texture library. No normal maps or shader graph yet.

## Gameplay and audio
Ordered event rules support start, collect, goal entry, respawn, checkpoint, jump, second, zone-enter and zone-exit, minimum score conditions and score, message, win or lose actions. A box assigned the trigger role is wireframe in the editor and hidden in play. It is nonblocking and uses the same conservative axis-aligned bounds as other triggers. Zone-enter and zone-exit fire on overlap changes, including entry when the player starts inside a zone. Multiple zones are independent; exits are processed before entries in authored object order. Respawn clears zone occupancy without synthetic exits. Collect, goal, checkpoint and zone rules may target a particular object in the active level or any matching object. Entering each goal fires its own event, even with overlapping goal bounds. Deleted or role-changed targets become inactive and appear in diagnostics. Reusable packs exclude object-specific rules. Named integer counters support add/set actions and optional >=, <= or equality conditions on any rule. Counters start at zero, reset on respawn and can be displayed in the configurable HUD. Solid objects can become counter-controlled gates: configure a named integer counter condition, with no code required. The same open-state set controls collision and rendering. Closing is deferred while a player or dynamic body overlaps the open gate; state is recalculated after events and respawn, with legacy solids unchanged. Disable automatic win when using a custom gated goal. No arbitrary scripts. Default win behavior can be disabled. Jump fires once on a grounded jump; second fires at whole simulated-second boundaries during active play (respawn takes priority). Second rules may specify a first second (1–3,600) and repeat interval (0–3,600 seconds; zero fires only at the scheduled second). The level clock continues through respawns and restarts with the level. Conditions are evaluated at scheduled ticks, not retried between ticks. A lose action ends the level and prevents automatic win or campaign advancement. The first explicit terminal action takes precedence within the simulation step; restart resets the level. Optional 1–99 starting lives are per-level; each hazard or fall consumes one life. The final death stops simulation without running respawn rules, preserves the last score and displays Game over. Unlimited lives remain the legacy default. Any rule can run once per life, consuming its flag only after conditions pass; respawn clears the flags. Duplicate rules receive new IDs and can be reordered in either direction. Hazard and collectible objects can use a repeating linear patrol with configurable offset and period; trigger collision and visual position share the same simulation clock. The patrol clock and dynamic object positions persist through player respawn but reset when the level restarts.
Audio Studio generates bounded synthesized oscillator sound effects for start, collect, jump, respawn, win, checkpoint and lose; adjust waveform, duration, pitch and volume. Browser autoplay restrictions require interaction. A local PCM16 mono/stereo WAV at 8–48 kHz and up to two seconds may override each event tone. Import validates RIFF bounds, downmixes and resamples to 16 kHz mono PCM, stores bounded Base64 samples (at most 24 references per project), and plays them through Web Audio in the editor and export. AI can edit tone parameters but cannot supply sample bytes; provider context exposes names and frame counts only. No compressed audio, spatial mixing or music timeline.

## Local multiplayer presence prototype
Start the local development server, open the same saved level in two browser tabs, and enter play. In Workspace → Projects, create a room or join its eight-character code. The loopback-only same-origin room endpoint holds at most 32 rooms of eight participants, validates bounded positions and level fingerprints, issues per-member random tokens, rejects stale or overly frequent updates, and expires idle members after 30 seconds. Remote participants appear as translucent ghost markers with interpolated positions; fingerprints normalize project defaults so reloaded copies match; display names and positions are shared only with the local room. Leave or stop play to disconnect. No shared collectibles, score, collisions, authoritative gameplay, internet matchmaking, or exported multiplayer. Do not expose the development server publicly.

## Local AI and GitHub integrations
Run npm run dev on localhost. AI Studio accepts a manually pasted JSON plan or requests a plan from OpenAI, OpenRouter or Anthropic using the local gateway. User consent is required before sending project context to a provider; charges may apply. Provider keys are transient and never serialized with projects. Generated commands are validated, reviewed and applied as one undoable edit. AI plans can add, duplicate (up to 200 source objects), rename or switch to known level IDs, and replace validated decorative transform animation clips. Explicit AI gameplay rules must reference existing compatible event objects; object, physics, rule, environment and audio edits apply to the active level. Environment and audio commands merge validated partial settings (including individual sound cues); presentation commands update the shared HUD and camera. The preview includes these settings changes. Review shows per-level changes, including automatic ground/player objects in a new level. The context includes level names and IDs but only active-level entity IDs. No code is executed.
GitHub project integration accepts a user-supplied least-privilege repository token, a target branch and a .game-studio.json file path. Inspect before committing; use the inspected file SHA for updates. Files are limited to 750 KB. Public repositories expose saved project contents. No OAuth, cloud synchronization, LFS or GitHub App yet.
The gateways are loopback and same-origin only, intended for local development. Do not deploy them publicly without authentication, rate limits, tenant isolation, secret management, abuse protection and security review. Live credentials and external provider calls have not been verified in CI.

## Limb inverse kinematics
Character Studio includes a two-link inverse-kinematics pose authoring control for each arm and leg. Targets use down/forward coordinates relative to the shoulder or hip, normalized to one limb segment. Choose the bend direction; unreachable targets and angles outside the existing ±120° limits are rejected. Solving changes only the two existing joint angles, so it is undoable, persists and can be captured in a timeline key. Automatic player locomotion can override authored poses during play. This is planar, equal-length procedural rig IK, not arbitrary imported skeleton IK, continuous target tracking or foot planting.

## GPU shader graph
Shader Studio accepts a bounded 1–16 node, topologically ordered color graph on primitives/custom meshes/terrain. It compiles to a local unlit GLSL material, with base color, RGB constants, coordinate gradients, repeating bands, mixing and multiplication. It uses the same renderer in editor and standalone games. Undo, reload and prefab appearance propagation preserve graphs. Applying a material preset or Restore PBR returns to the regular PBR renderer; PBR settings are retained while the graph is active. Imported models and articulated characters do not support graph overrides. GLB mesh export remains solid PBR only. No arbitrary GLSL, textures in graphs, lighting nodes, external resources or shader imports; this is a basic shader editing workflow, not a full professional node editor.

## Non-destructive mesh modifiers
Custom meshes can preserve a source mesh and evaluate an ordered stack of up to four operations: shared-edge subdivision, Loop smoothing, mirror or an axis-aligned box Boolean as the first step. A box Boolean uses the standard cuboid source topology and an independently positioned/sized rectangular cutter; union, difference and intersection use exact coordinate-cell surface extraction and reject empty, ambiguous touching and non-manifold results. This is not general arbitrary-mesh CSG. The evaluated mesh is used consistently by rendering, GLB export and the existing conservative collider; holes are visual only under bounding-box collisions. Remove restores the source; bake retains evaluated geometry and re-enables direct topology editing. Undo, reload and prefab propagation retain both source and stack. A project is limited to 32 modifier object references. Import verifies the evaluated geometry cache against its source and stack; topology and coordinate quotas remain active.

Shader graphs are capped at 64 references per project, including inactive levels and prefab sources, to bound shader program churn. A graph cannot be saved as a PBR material preset; restore PBR or apply a saved PBR preset. Browser regression also checks the actual rendered canvas pixels for a shader-only color change.

Both shader and modifier drafts now have visual form controls: add bounded nodes/steps, choose input references, colors, blends, axes and box cutter dimensions, and reorder/remove modifier steps. Advanced JSON remains available for copying and precise edits. Changes remain drafts until Apply, with a single undoable commit.

## Weighted skeletal limbs
Character Studio offers optional smooth weighted limb meshes. Each arm and leg has two hierarchical joint transforms and a continuous tube with interpolated weights around the joint; CPU linear blend skinning updates vertex positions and normals in the shared editor/player renderer. Bind pose, blended joint transforms and endpoints have numerical tests. Rigid articulated parts remain the default. Smooth skinning is limited to procedural limbs, not arbitrary imported mesh weight painting or full-body skinning.

## Animation blending and retargeting
Decorative characters can blend a secondary canonical joint clip into their primary clip or rest pose with independent speed and weight. Copy clips from another character with different proportions or import named scalar channels through an explicit source-name/sign/rest-offset map. Each mapped key is validated against the canonical nine joint limits; the renderer samples both clips during preview and play. This supports the procedural sagittal rig, not arbitrary imported quaternion rigs, root motion or professional motion matching. Player locomotion remains separate.

## Asynchronous collaborative editing
Export a common base project and share it with a teammate; each author edits independently. Collaborative project merge takes that base, the current local workspace and an incoming JSON snapshot. It normalizes active-level selection, merges independent stable-ID changes, surfaces conflicting fields/deletions/order for explicit resolution, and validates all project invariants before applying one undoable change. Stale reviews cannot overwrite newer workspace edits. This is asynchronous file-based collaboration, not live co-editing, CRDT transport or automatic Git conflict commits. Geometry, animation and other coupled structures are treated conservatively; invalid combined projects require separate edits.

See [game generation evaluation](game-generation-evaluation.md) for the exact scope, and optional real-provider test. Live AI output quality is not inferred from fixtures.

## Runtime profiling
Graphics and performance reports an active gameplay window of up to 180 frames: frame interval, simulation CPU and render-submission CPU p95. The window resets on new play, stop and context loss; inactive, paused and completed play do not add samples. Render-submission CPU is not GPU execution time. Reference browser profiles use the defined desktop and compact viewport settings; physical-device validation is still required.
