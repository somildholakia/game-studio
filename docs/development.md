# Development and creator workflows

Node.js 22+. Run npm ci, npm run dev, npm test and npm run build. Dev and build generate an embedded IIFE player bundle. The development server binds to loopback; the built static editor does not expose credentialed integrations.

## Playable games
Load Treasure Run, Sky Steps, Meadow Explorer, Physics Playground or the two-level Adventure Campaign. Press Play; move using WASD, arrows, on-screen controls, or a standard gamepad's left stick or D-pad. Jump with Space, Jump, or the gamepad's primary button. Gamepad stick input uses a dead zone; browser support and device behavior still need real hardware verification. Collect items and reach the goal. Stop restores the authored scene. Assign roles (decoration, player, solid, collectible, goal) to supported primitives and characters. One player per scene. Hazard objects respawn the player; checkpoints change the current respawn location and dispatch a checkpoint event. Score and collectibles reset on respawn. Keep checkpoints and their respawn locations clear of hazards and solid geometry. Undo/redo, project JSON export and self-contained HTML game export are supported. No native executable builds or multiplayer yet.

## Level Manager and game presentation
Create, duplicate, rename, reorder and delete up to 32 levels; a duplicate is inserted immediately after its source and activated. It receives independent scene settings, objects and rule IDs, with event-object references remapped to the copies. Assets and prefabs remain shared; editing switches the active scene while assets and prefabs remain shared. Each level has its own entities, physics, logic, audio and environment. The active scene is autosaved along with all inactive levels. Undo restores previous edits including level deletion. Play tests the current level; Play campaign starts at the first level, and Next level appears after completion. HTML export includes the full ordered campaign, uses the project name as an escaped HTML title, and declares a content security policy allowing the bundled runtime and embedded assets but denying remote connections and scripts. The policy is scoped to the exported game, not a production editor deployment. Every campaign level needs a player and a goal with auto-win enabled or a win rule. This validates structure, not solvability. Score and progress reset between levels; no save-game system or branching scene graph yet.
Game UI and camera controls customize HUD title, text color, score, collectibles, messages and follow/overhead camera distance. Workspace and inspector filters and scene search organize editing controls. Rendering quality is global: resolution scaling, optional directional shadows and 512/1024/2048 shadow maps. Diagnostics report approximate FPS, scene mesh/vertex counts and render-buffer dimensions. These are local observations, not a production performance benchmark.

## Project management and assets
The active workspace autosaves to IndexedDB. Legacy localStorage data migrates without deleting its old backup. The named project library stores independent snapshots; Save project copy, Open, Update or Delete explicitly. These are snapshots, not multiple automatically saved live workspaces. Browser storage can be evicted; export backups. Current editor tabs compare a workspace revision atomically before each autosave. If another tab has saved first, autosave is disabled and the unsaved scene remains available for export; reopen the latest saved project or explicitly confirm replacement. Close older-version editor tabs before using this feature, since their saves do not participate in the revision protocol. This is conflict detection, not collaborative merging.
Import a self-contained uncompressed GLB (2 MiB per file, 3 MiB aggregate); external URIs and glTF extensions are rejected. Models retain their materials and are decorative. The importer also checks embedded buffer/view and accessor ranges (including strides and sparse declarations), with at most 250,000 elements per accessor and a conservative 16 MiB aggregate decoded-accessor budget. Scene graph checks also reject cycles, multiple parents, duplicate scene roots, invalid node/mesh references and hierarchies deeper than 64 nodes, with limits of 2,048 nodes, 64 scenes, 512 meshes and 4,096 declared or instantiated primitives. This does not validate every glTF reference, decoded image dimension, or renderer allocation; it is not a full security validator. Prefabs can be placed as independent snapshots or linked copies. Explicit Update from selected propagates geometry, character customization, material and asset changes to linked objects across all levels, preserving each object's name, transform, role and animation. Detach turns a linked instance into an independent object. Removing a prefab detaches its instances; no nested inheritance or automatic live propagation. Extension packs export and import validated prefabs, referenced models and declarative gameplay rules, with fresh IDs. They are data-only, not executable plugins.

## Physics and editing
Static swept axis-aligned collisions, gravity, jumping, raised platforms, respawn, height-aware triggers and fixed-substep integration. Direct move/rotate/scale handles with optional snapping and undo. Character collisions remain conservative bounds. Dynamic primitive objects now use bounded translational AABB physics. Assign the dynamic role and configure mass (player push response), restitution, ground friction and initial velocity. Up to 64 per level; they fall, bounce, block the character and may be pushed. Simulation is separate from authored state. This is a lightweight ordered collision solver, not a full rigid-body engine: no angular motion, joints, true sphere/mesh contacts, conservation of momentum, robust stacks or moving platforms. Bodies should start above surfaces and outside obstacles. Terrain contact is conservative; upward steps can block objects.

## Terrain and environment
Create a terrain object and edit its seed, grid resolution, amplitude and frequency. It uses deterministic triangle heights for rendering and center-point ground contact; terrain is axis aligned with positive scale and cannot be assigned another gameplay role or animated. Large cliffs, overlapping heightfields and extreme scales have limitations; this is not general mesh collision. Meadow Explorer is a terrain example.
Environment Studio sets sky/background color, ambient and directional light, sun direction, intensity and color, and exponential fog. Day, sunset and night presets are static settings, not an animated weather system. Optional directional shadow maps are available; no HDR environment map or volumetric lighting yet.

## Modeling, characters and animation
Model Studio supports editable cube topology, numeric vertex editing, vertex duplicate/delete, triangle add/delete, subdivision, validation and flat shading. Limits: 2,048 vertices and 4,096 triangles per mesh. Custom models are decorative. Select Pick vertex in viewport, then click a visible triangle to select its nearest vertex; an editor marker highlights the chosen point. Numeric local-space coordinate editing remains the way to move vertices. Triangle extrusion, face winding reversal, whole-mesh reflection, tolerance-based vertex welding, and OBJ import/export are supported. Subdivide entire mesh splits every triangle into four with one shared midpoint per edge, retaining shape and winding. The operation is undoable and rejects changes exceeding topology limits; it is not a smoothing subdivision surface. Custom meshes can also export a self-contained GLB containing local geometry, flat normals, projected UVs and solid PBR color/metallic/roughness/emission factors. Procedural textures, transforms, gameplay and animation are not included in this model export. OBJ import is geometry-only, with bounded vertices and triangles, negative indices and fan triangulation of convex polygons; normals, UVs, material files and external references are ignored. Local inflate, deflate and smooth brushes operate around a selected vertex with adjustable radius and strength; each stroke is an undoable edit. This is a low-resolution vertex operation, not continuous brush painting or adaptive remeshing. Custom meshes support automatic dominant-axis UV projection or explicit XY/XZ/YZ projection. No UV island editor, direct vertex dragging or Boolean tools.
Characters are procedural articulated low-poly figures with adjustable proportions, skin, clothing, hair, shoes, and nine joint angles. Automatic walking and jumping poses drive the player when enabled. This is a rigid mesh hierarchy, not skinned skeleton animation, inverse kinematics or motion retargeting.
Transform keyframes support decorative objects, linear, smooth ease-in/out or stepped interpolation, forward and ping-pong looping, and scrubbing. Older clips default to linear forward looping; the editor preview remains a single forward pass. Ground, terrain and gameplay roles are excluded to preserve static collision. PBR primitive materials support color, roughness, metallic and emission. Optional procedural checker, brick, stripes, grid and noise textures are generated locally as bounded RGBA images with tint and independent UV repeats. They are stored as parameters, not external resources. No image texture import, normal maps or shader graph yet.

## Gameplay and audio
Ordered event rules support start, collect, goal entry, respawn, checkpoint, jump and second, minimum score conditions and score, message or win actions. Collect, goal and checkpoint rules may target a particular object in the active level or any matching object. Entering each goal fires its own event, even with overlapping goal bounds. Deleted or role-changed targets become inactive and appear in diagnostics. Reusable packs exclude object-specific rules. Named integer counters support add/set actions and optional >=, <= or equality conditions on any rule. Counters start at zero, reset on respawn and can be displayed in the configurable HUD. Disable automatic win when using a custom gated goal. No arbitrary scripts. Default win behavior can be disabled. Jump fires once on a grounded jump; second fires at whole simulated-second boundaries during active play (respawn takes priority). Hazard and collectible objects can use a repeating linear patrol with configurable offset and period; trigger collision and visual position share the same simulation clock. The patrol clock and dynamic object positions persist through player respawn but reset when the level restarts.
Audio Studio generates bounded synthesized oscillator sound effects for start, collect, jump, respawn and win; adjust waveform, duration, pitch and volume. Browser autoplay restrictions require interaction. No audio file imports, spatial mixing or music timeline.

## Local AI and GitHub integrations
Run npm run dev on localhost. AI Studio accepts a manually pasted JSON plan or requests a plan from OpenAI, OpenRouter or Anthropic using the local gateway. User consent is required before sending project context to a provider; charges may apply. Provider keys are transient and never serialized with projects. Generated commands are validated, reviewed and applied as one undoable edit. AI plans can add, duplicate (up to 200 source objects), rename or switch to known level IDs, and replace validated decorative transform animation clips. Explicit AI gameplay rules must reference existing compatible event objects; object, physics, rule, environment and audio edits apply to the active level. Environment and audio commands merge validated partial settings (including individual sound cues); presentation commands update the shared HUD and camera. The preview includes these settings changes. Review shows per-level changes, including automatic ground/player objects in a new level. The context includes level names and IDs but only active-level entity IDs. No code is executed.
GitHub project integration accepts a user-supplied least-privilege repository token, a target branch and a .game-studio.json file path. Inspect before committing; use the inspected file SHA for updates. Files are limited to 750 KB. Public repositories expose saved project contents. No OAuth, cloud synchronization, LFS or GitHub App yet.
The gateways are loopback and same-origin only, intended for local development. Do not deploy them publicly without authentication, rate limits, tenant isolation, secret management, abuse protection and security review. Live credentials and external provider calls have not been verified in CI.

## Project diagnostics
The Projects workspace lists structural issues across all levels, including missing player/win rules, initial solid or hazard overlap, near-zero scales and dynamic body limits. Checks are heuristic, not a proof of playability, security or performance.

## Verification
Run npm test, npm run build, npx playwright install chromium, npm run test:e2e. CI includes software WebGL Chromium tests for authoring, persistence, play, export, gameplay, mesh/animation, AI plan approval, terrain, character controls, campaign transitions, workspace filters, HUD and graphics settings. Local gateway tests use mocked upstream responses. See release-gates.md for the production checklist. A separate browser compatibility workflow configures Chromium, Firefox and WebKit with software rendering and runs on relevant pull request changes. Manual dispatch depends on the workflow reaching the default branch. The workflow configuration is not a verified support matrix. Real hardware and mobile browser testing remain necessary. No full engine parity or million-user claim.
